# Wavelink — private, fictional client demo on a cloud server

**Deployment package:** `client-demo-2026-09-24-r1`  
**Application baseline:** verified Wavelink 1.34.19.  
**Purpose:** demonstrate existing browser workspaces without running Windows Admin or leaving a laptop switched on. **Not approved for real operational, personal or confidential data.**

This is an executable deployment candidate, unlike the earlier preparation-only ZIP. It includes the Dockerfile, a same-container gateway, an independent invitation gate, one-time headless fictional-data provisioning, the exact upstream source (split into five upload-friendly parts), and the recovery helper. It does NOT create a GitHub repository, purchase hosting, deploy a Render service, register a domain, or change the vessel installation or CCVD.

**Current limitation:** the Docker image has not been built here and the service has not been deployed to Render. Local Python/Nginx/HTTP/WebSocket tests passed; real browser navigation was blocked by this execution environment. The Render build, real TLS ingress, browser acceptance, volume persistence and recovery rehearsal are launch checks, not claimed accomplishments. Current provider prices, plan names and dashboard labels could not be verified because web search was unavailable.

## 1. Upload to a NEW private GitHub repository

1. Extract `Wavelink_Client_Demo_Render_GitHub.zip` on your computer. Open its `Wavelink_Client_Demo_Deploy` folder.
2. Sign in at `https://github.com/`. Create a new repository named **`wavelink-client-demo`**. Select **Private**. Do not reuse, rename or replace a CCVD repository.
3. On the empty repository page, use **uploading an existing file**. On a repository with a README, use **Add file → Upload files**. These are familiar UI labels, not a live-verified screenshot of today's interface.
4. Drag the **contents** of the extracted folder into the upload area. Include the folders, five `vendor/source.part...` files, `vendor/source_parts.json`, the fictional seed, and `.gitignore` / `.dockerignore`. Do not upload only the outer ZIP.
5. Commit the files with a message such as **Initial fictional Wavelink client demo**.
6. Check that **Dockerfile** and **requirements.lock** appear at the repository's top level, beside `deploy`, `ops`, `vendor`, `tests` and `docs`. Do not put everything one extra directory below the root.

The five source parts are each at most 8 MiB. The container reassembles them and verifies the original complete source checksum and all 1,605 tracked source files. Do not rename or edit them. GitHub Desktop can also publish the same folder, but it is not required to run the hosted application.

Never commit actual project databases, `hub.json`, passwords, `.env`, signing/recovery keys or backup files. This package's `.ajproject` is a reviewed fictional seed with its published login hashes retired. Your new passwords belong in the hosting service's protected environment settings, not the repository.

## 2. Create a separate Render service

Open `https://dashboard.render.com/`. Choose the equivalent of **New → Web Service**, connect GitHub, and select **only the new Wavelink repository** for this service. When updating repository permissions, add this repository without revoking or altering existing CCVD access.

| Setting | Value for this candidate |
|---|---|
| Service | New paid **Docker Web Service** with a persistent disk |
| Name | `wavelink-client-demo` or another available separate name |
| Branch | The branch containing the files, usually `main` |
| Root directory | Blank when Dockerfile is at repository root |
| Runtime | Docker |
| Dockerfile path | `./Dockerfile` |
| Docker build context | Repository root (`.`), where that field exists |
| Start command | Use the Dockerfile CMD. Do not substitute a generic Uvicorn command |
| Compute | Start with at least 1 vCPU and 2 GiB RAM for a small fictional demonstration; not a production benchmark |
| Instance count | One; disable horizontal autoscaling |
| Persistent disk | 10 GiB, mount path **`/var/data`** |
| Health check | **`/healthz`** |
| Automatic deploys | Disable for the client presentation; deploy deliberately |
| Database add-on | None. This build uses SQLite WAL on the disk, not PostgreSQL |
| Public port | Platform `PORT` is used; fallback is 10000. Private ports 8765/8766 stay internal |

Confirm the actual available instance size, disk support, region and displayed charge in Render before purchasing. Do not choose an ephemeral-only/free configuration as a substitute. If the disk can only be attached after service creation, attach it and redeploy: the launcher refuses to run without the mount and does not seed into temporary storage.

A different provider can satisfy the same container/volume contract, but this package contains no verified provider-specific Blueprint and no promise of current platform compatibility.

## 3. Add these protected environment variables

Use two different newly generated passwords from your password manager. Do not use the examples from tests, a demonstration password printed in old guides, or the same password twice.

| Name | Value |
|---|---|
| `DEMO_ACCESS_PASSWORD` | A new random 20–128-character invitation password. Keep it for restricted demo visitors. |
| `INITIAL_ADMIN_PASSWORD` | A different new random 20–128-character password for **`adriano.admin`**. First initialization only. |
| `INITIALISE_FICTIONAL_DEMO` | **`YES_FIRST_DEPLOY_ONLY`** for the first initialization; change to **`NO`** immediately afterwards. |
| `PUBLIC_URL` | The exact HTTPS address assigned to this new service, with no path, such as the actual `https://…onrender.com` address. |

If the address is not yet shown, the package can read `RENDER_EXTERNAL_URL` or `RENDER_EXTERNAL_HOSTNAME` **when the platform supplies them**. If neither is available, startup stops with a request for `PUBLIC_URL`. Copy the actual assigned URL into that variable and redeploy; do not invent a hostname.

Do NOT add `DATABASE_URL`, `WEB_CONCURRENCY`, `UVICORN_*`, local vessel paths or CCVD secrets. Do not bind the inner hosted launcher publicly. The gateway listens on the public platform port; Wavelink itself stays on 127.0.0.1:8765 with one worker.

The access-cookie signing key is generated on the server and retained in `/var/data/wavelink/operator/gate.key`. It is not a value to paste into GitHub.

## 4. Deploy and complete the one-time setup

1. Start the service deployment. Review its build/runtime logs for an actual successful build and healthy service.
2. On its first authorized run the server imports only the supplied fictional seed, assigns a NEW hub identity, retires the published demo logins and enables **`adriano.admin`** with your password. No Windows Admin is opened.
3. Open the assigned HTTPS address. You should see **Welcome to the Wavelink demonstration**.
4. Enter `DEMO_ACCESS_PASSWORD`. Then sign in to Wavelink as **`adriano.admin`** using `INITIAL_ADMIN_PASSWORD`.
5. In Render, set **`INITIALISE_FICTIONAL_DEMO=NO`**, remove **`INITIAL_ADMIN_PASSWORD`**, and apply/redeploy. Keep `DEMO_ACCESS_PASSWORD` and the correct `PUBLIC_URL`.
6. Sign in again as needed. Confirm that the hub, sample records and administrator account remain. The initial password is already hashed in the database; removing its environment variable does not delete or reset the account.

**Do not leave initial seeding enabled.** An initialized directory with missing files is always rejected, but a completely empty replacement disk could look like a first installation while first-deploy authorization remains enabled. Once set to NO, an empty/missing database stops startup rather than silently creating another demo.

Do not delete locks, the deployment identity, SQLite sidecars or `hub.json` to make a failed startup continue. The normal shared app locks prevent cooperating concurrent writers; they are not distributed locking or a guarantee that provider replicas can safely share a volume.

## 5. Use the browser for administration and the presentation

Open **Administration** in the sidebar. The existing browser interfaces manage named users, departments and permissions; Company branding handles the report identity. The package retains the inventory, nested boxes, manifests, receiving, Tasks, checklists, handovers, Fault Reports and HSE/QSHE workspaces.

Create a named client demonstration account through Administration and review its access. Do not give the client your administrator password or hosting/GitHub access. The visitor needs both the invitation password and their personal Wavelink account. For a supervised presentation you can demonstrate your own account over a screen share, rather than granting management rights to the client.

The four former sample users stay disabled. Their fictional author/assignment history is retained. To use a sample role deliberately, reset its password through browser administration **before** enabling it. Do not publish the old training credentials.

Useful demonstration order: Home → Inventory (open a box, then a nested case) → Asset details → Manifests → Receiving & placement → a Task/checklist → a handover → Fault Reports/HSE → company-branded report. Do not present unfinished or unsupported functions as finished.

**No laptop or Windows Admin needs to stay on after deployment.** Not every desktop utility has a browser equivalent: bulk project/import setup and disaster recovery remain server-operator procedures. Preloading the fictional project avoids needing desktop import tools for this demonstration. Existing help for some local-vessel functions remains in the application. A few sign-in/connection/help labels are changed at the gateway for this demo only; original documents, reports and JSON evidence are never rewritten by that presentation rule.

## 6. Rehearse before inviting the client

- In an incognito browser, confirm that app/API/file routes do not bypass the invitation gate, wrong passwords fail, and a limited account cannot open administration.
- In your administrator session create a temporary fictional Task or inventory item, refresh, then restart/redeploy the service. Confirm the exact same record and project remain. Check an uploaded fictional PDF/image after restarting too.
- Use desktop and phone browsers through the real URL. Try inventory boxes, a saved manifest, receiving, report downloads and WebSocket-driven updates. Verify no new login/window appears unexpectedly.
- Test the provider-assigned hostname and any custom hostname. Only the configured canonical application hostname should work, except for a minimal anonymous health probe. Do not weaken the host/proxy checks to suppress an error.
- Take a recovery copy and practise restoring it before introducing anything important. A healthy homepage or a platform “Live” badge is not proof of these results.

The invitation gate is a shared, high-entropy demo password with a signed Secure/HttpOnly/SameSite cookie, an eight-hour admission lifetime and throttled login attempts. **It is not named identity-provider SSO, an identity allowlist, MFA, production internet hardening or tenant isolation.** Wavelink accounts remain individual and separate. Rotating the invitation password and restarting rejects old gate cookies. Already-open connections should be closed by a deliberate restart when removing demo access; downloads or previously retained browser data cannot be recalled.

The existing application password rules are unchanged and can accept shorter passwords elsewhere. Use long passwords for every test account; hosted-wide hardening remains a real-data requirement.

## 7. Add the domain after the assigned URL works

Do not wait for `mywavelink.com` to finish registration before testing the application. Domain purchase, ownership and DNS have not been verified here.

For the final presentation address, add **`demo.mywavelink.com`** as a custom domain in the new service. At your DNS provider, create exactly the record Render specifies. Do not guess the destination or change CCVD's DNS. After the certificate/domain is actually ready, set `PUBLIC_URL=https://demo.mywavelink.com` and redeploy deliberately. The old hostname should stop serving the app; the health probe can remain minimal/public.

Preserve or synchronise any unsent browser work **before changing hostname**. Existing browser drafts do not move between origins. Complete the hostname change before sending the final client link.

## 8. Storage, backup and recovery boundaries

Persist the entire `/var/data/wavelink` directory. The database holds original documents, photographs, certificate files, manifest attachments, checklist photo evidence, log media and branding; an “uploads” folder alone is not sufficient. Application source remains in the replaceable image. Browser-only unsent work is not in a server backup.

The normal browser menu can export a sensitive unencrypted database snapshot with explicit review. That download is **not a complete encrypted recovery of this container**, because the private hub identity, hosted configuration and deployment/gateway metadata also matter.

The inherited encrypted operator helper is included at `/opt/wavelink/ops/staging_recovery.py`. Read `docs/RECOVERY_HELPER.md` for its exact commands and 500 MB pilot cap. It backs up/restores the prepared database, private hub.json and hosted.json, not this wrapper's DEPLOYMENT.json or gate.key. Preserve those additional metadata files through an authorized encrypted operator backup, or deliberately rebuild the demo wrapper after validating the recovered identity. Never place those secrets in Git or an unencrypted public archive.

Actual off-host transfer, scheduling, a one-click browser restore, provider-disk recovery, and a complete wrapper restore rehearsal are NOT delivered or tested here. No real data until they are implemented/rehearsed along with authentication, company/project isolation, browser administration and restart/update persistence. The previous recovery runbook remains a foundation, not approval for production.

## 9. Troubleshooting checkpoints

| Symptom | Check |
|---|---|
| Dockerfile cannot be found | Repository root/nesting and the selected branch. Do not upload only a ZIP. |
| Missing source part or checksum failure | All five source parts plus source_parts.json, unchanged. |
| Image/package build fails | Capture the actual build error. Dependency versions and base image have not been fetched/built here; do not substitute arbitrary versions without retesting. |
| Persistent disk required | The disk must be mounted at exactly `/var/data`. No ephemeral fallback. |
| PUBLIC_URL requested | Enter the exact assigned HTTPS origin and redeploy. |
| Startup refuses the data directory | Check retained volume/identity; do not delete files or re-enable seeding over lost work. |
| 400/421 through the real address | Canonical URL, Host and the real TLS forwarding header. Provider integration must be inspected, not disabled. |
| Login gate works, app login fails | `adriano.admin`, the first administrator password, and whether an existing project was retained. Restart does not reset passwords. |
| An expired gate returns a JSON message | Preserve unsent work; open `/__demo/login` in the same browser/account context. Do not clear browser storage. |

Keep the running vessel installation and CCVD relay entirely separate. This is NOT vessel/cloud synchronization or a copy of your active operational database.
