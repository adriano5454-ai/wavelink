## Visible Upload original and New folder

Open **Documents → Original files**. Upload original and New folder stay above the search on phones,
using UI60's shared controls. They appear only when permitted. Browse folders, All files, Library root,
search across all folders, Include archived revisions and exact selections remain.

New folder is **name → destination → Create folder**, without a typed generic reason or a review page.
A first upload or additional revision is **file → title/revision → destination → Upload original**.
File notes are optional. No import reason or routine review checkbox is required; the named actor,
time, actual action, file fingerprint and existing receipt/audit remain. No fictional explanation
is inserted into the record.

Adding a revision requires its source-revision label and keeps the original family. Older bytes, IDs and
procedure links remain unchanged. Earlier revisions are not automatically archived or made obsolete.
A deliberate new-family upload of the same bytes is not prevented by global deduplication; retrying the
same operation remains duplicate-safe.

Browser limits remain one file at a time, 20 MB, 500 library revisions, 200 folders, six folder levels
and up to 100 exact revisions per reviewed move. PDF, DOCX, PNG/JPEG and supported Excel families remain.
The complete original can include hidden sheets, macros, connections and metadata. Format validation
is not antivirus, issuer verification or operating approval. Native advanced Excel transfer remains separate.

## Explicit Original documents permissions

A named administrator opens **Administration → People & access → person → Project permissions**.

| New permission | Authority |
|---|---|
| Upload new originals and add source revisions | Upload into a chosen existing folder; retain earlier revisions. |
| Create and organise original-file folders | Create/rename/move/remove empty folders and move exact source revisions. |
| Archive and restore original-file revisions | Reversibly change the selected source revision's archived state. |

Each requires **View and download original documents**. The three actions start OFF for all non-admin
accounts; existing administrators retain full access. Grant only the needed actions to a Technician or
Supervisor without administrator promotion. A builder grant does not also grant upload or organisation.
The existing permission editor requires a meaningful access-change review and revokes that person's
sessions; preserve their work and sign back in with the same account.

Folder organisation does not grant source lifecycle management; upload does not grant moving existing files.
Folders do not make private audiences. People/account administration and native permanent deletion remain
separate. Existing source viewing rules remain project/module-scoped.

## Source details, history and reversible lifecycle

Details shows exact metadata and **Revisions of this document**, **Used by** and **Source history**.
Source history is the latest 100 original-source events, with the total and truncation indicator. Folder
history remains a separate organisation-permission view of the latest 100 folder operations.

Used by shows only definition/checklist/maintenance references permitted by the current account.
It lists up to 500 permitted rows with total/truncation, not a hidden total of inaccessible records.
It is read-only reference information, not a complete dependency scan authorising deletion or a grant
to open another module's private records.

Archive/Restore needs its explicit permission, a meaningful explanation and an initially unchecked
confirmation. It checks the same full library snapshot again inside the transaction, preserving bytes,
references and an exact operation receipt. Only the selected revision's archived flag changes.
**Permanent deletion is not available in this browser update.**

Rename, move, remove empty folder and move revisions retain their existing consequential reviews,
scope checks and reasons. Archived revisions and subfolders still count as contents; a folder must
truly be empty before removal. Search/folder/archive-filter changes clear selection. Refresh also
clears selected revisions explicitly so no old move authority is carried into another snapshot.

## Connect a source to a checklist or maintenance routine

Open the permitted **Checklist** or **Maintenance routine** builder and choose **Original sources**.
With the corresponding builder permission plus Original documents viewing, search the active revisions
and choose **Link revision** beside the exact title/revision/filename. Inspect selected references,
remove/re-add deliberately, and then **Save draft**.

Selection changes only the proposed definition. A separate saved-draft review and publication still
apply. Existing published templates, completed or open checklist runs and maintenance work orders
retain their own source references. Up to 12 exact sources can be selected. Adding an original revision
never updates every linked procedure automatically.

The service verifies the exact metadata/fingerprint against the saved source. Newly choosing an archived
source is refused; unchanged retained archived links can stay. Removing a link from this draft does not
delete the source or erase earlier evidence. Old clients omitting the optional source_documents field
preserve saved references. Reference pictures, deeper import/conversion review and permanent native
deletion remain separate capabilities. This is not automatic PDF-to-procedure conversion.

## Preserve unsaved forms and your position

A pending Folder history response is invalidated when leaving that view. It cannot blank a newer folder
name or remove a selected upload. Source details and builder source-catalogue requests also remain scoped
to their originating account/view/editor. Later requests cannot take over a different form.

Manual refresh retains the search, Browse folders disclosure and dialog reading anchor where it still
exists. It deliberately clears move selection. A temporary failure labels the last saved view and blocks
stale record actions, including after searching it. A definitive viewing denial on the checked read or
download clears obsolete displayed metadata without deleting separate unsaved wording. The library has
no new automatic polling interval; UI55's quiet shared caching and UI60 presentation remain intact.

File selections, folder/lifecycle proposals and source-builder edits are **in-tab until explicitly saved**,
not new durable offline drafts. Pending file preparation/upload blocks ordinary Close/Escape and main
sign-out. Existing before-send account checks remain. A lost response retains the same operation/file;
use **Retry same upload**, **Check saved upload outcome** or the corresponding same-operation retry.
Closing an uncertain form cannot undo a request already sent; check its saved outcome before another action.
