## Find the signed guest on the actual document

Open the saved **Toolbox talk** or the **published handover**, then **Participants & signatures**.
The view now combines native acknowledgements with verified invitation evidence for that exact saved
revision. It shows the saved name, identity type, UTC signing time, receipt and any original drawn mark.
Drawings are visible directly instead of being available only in the invitation manager's disclosure.

**Refresh** on Toolbox Talks and **Refresh participants** on an open handover reread saved participation.
Hiding the organiser's invitation panel also refreshes that document's participants. The original
invitation manager and dedicated signing reports remain available, and their expanded mark is preserved
through unchanged refreshes. My shift does not acquire unrelated team/publication panels.

Toolbox viewers retain the existing document-level participant view. For handovers, **the author sees
all recorded participation; another reader sees only their own account acknowledgement**. This does not
grant a recipient access to the visitor roster, another person's private draft or the wider project.
Visitors remain separate temporary identities, never shared-demo or invented project user accounts.
Names alone are not used to merge people: two different visitors with the same name remain distinct.
Facilitator-recorded guest acknowledgements retain the original typed name, method and recording account.

A drawn mark is not proof of verified identity or physical attendance. Listing a person is not signing
for them. The existing declaration and explicit Sign & finish action are unchanged. Signing expiry,
revocation, receipt retry, guest-only scope and current permissions remain enforced.

## Normal PDFs include the saved participation

The usual Toolbox **Export PDF · with signatures**, handover **Export displayed published PDF** and
combined subject journal now include the participation authorised for that viewer and each exact
revision, including the saved drawn marks. Original file bytes are not newly embedded; shared-file
names remain identified. The separate signing PDF still provides the detailed invitation read sets,
full issued snapshots and older signed revisions. It has not been replaced or reissued. Normal participant
rows keep the name, drawing and receipt together; oversized entries can still continue across pages.

A handover journal applies each record's author/reader boundary separately. It retains its existing
200-publication/text bounds and additionally refuses more than **500 participant rows**. A single
revision with more than **300 invitation signatures** requires the existing raw signing-evidence export.
No participant is silently truncated. Unavailable/inconsistent evidence blocks that PDF rather than
producing a report which pretends there were no signatures. Refresh if new signing evidence arrives
during the report; exporting never signs, completes or republishes anything.

Earlier signatures remain on the wording originally signed. A later revision can correctly have no
signatures even when an earlier revision does; the normal view identifies other signed revisions,
and the author can open their retained signing reports. No signatures are copied to new wording.

## Existing guests do not need to sign again

This update reads the existing UI34+ evidence format without modifying the signature writer, database
schema or saved receipts. A real local UI58 project was signed, closed, then reopened using this update:
normal views/PDFs displayed the original names and vector marks while signature rows and user count stayed
unchanged. No synthetic attendee repair or second signature was used.

This does **not** prove the user's live signing attempt reached the saved-receipt stage. Drawing alone,
a closed unsent form, an expired admission or a failed request cannot be reconstructed as a signature.
A later attempt by an already-acknowledged account also does not retroactively invent a missing mark.
Keep the actual receipt and correct document/revision; do not delete it, reset it or ask everyone to
resign as a troubleshooting step. Use the creator's account when checking the full handover roster.

## Consistent local forms and Toolbox entry

Inventory Saved forms, Maintenance Saved forms, Certificate Local forms and Toolbox Local forms now
list **that section's stored forms for the same account/project**. Each has an explicit **Manage all
unsaved work** action. The main Account list still opens all operation forms. Unknown form types remain
in the global list; entries, original versions, uncertain requests and unknown JSON fields are not
moved, rewritten or deleted by this filtering. In-tab-only wording remains distinct from a stored draft.

Toolbox Talks now exposes **New toolbox talk** separately from permissioned **Create form / Import form /
View forms**. These use the existing browser builder and .ajtoolbox importer; no administrator promotion
or automatic new permission is needed. A new briefing still requires a published form chosen deliberately.

The original Toolbox account/editor is checked immediately before sending, after the write-lease wait.
A definitely-unsent obsolete form cannot submit under another account. A late History/directory response
or old completion cannot replace a newer editor or remove its local draft. Already-sent requests may still
commit; preserve their exact operation identity for retry and do not fabricate an alternative request.

Toolbox refresh retains unchanged participant canvases and unrelated cards. Temporary failures show a
last-saved view with stale record actions disabled; definitive denial clears the protected background,
even behind an editor, without deleting its wording. UI55 quiet cache writes, real save warnings,
synchronisation, existing sign-out and bulk local-work protections remain.
